# FL0028: Avoid repeating the cancellation check immediately after `AsyncMethodContext.Switch`

`Libronix.Utility.Threading.AsyncMethodContext.Switch(SwitchToken)` checks cancellation on its receiver. When the token is produced by an awaited expression, this check happens after the await resumes. An immediate `ThrowIfCanceled()` on the same context usually repeats that cooperative cancellation checkpoint.

```csharp
context.Switch(await context.ToThreadPool());
context.ThrowIfCanceled(); // FL0028
```

Prefer a single checkpoint:

```csharp
context.Switch(await context.ToThreadPool());
```

The token does not identify which context is checked: `context.Switch(await other.ToThreadPool())` checks cancellation on `context`, not `other`. A check inside `Switch` cannot avoid scheduling or evaluating its awaited argument; this rule does not recommend removing cancellation checks before a switch.

This warning applies only to adjacent expression statements in the same block, switch section, or top-level statement list. Both calls must bind to the expected methods and the same stable ordinary local or by-value parameter. Comments and whitespace are allowed between calls. Intervening work, control flow, directives, different bindings (including aliases), fields, properties, indexers, dynamic or conditional access, ref bindings or escapes, reassigned bindings, captured bindings, and generated code are excluded conservatively.

This is a cooperative-cancellation convention, **not proof that the second call is dead code**: cancellation may arrive between the two checks. If the second checkpoint's distinct timing is intentional, keep it and suppress FL0028 locally:

```csharp
context.Switch(await context.ToThreadPool());
#pragma warning disable FL0028 // Intentionally observe cancellation again here.
context.ThrowIfCanceled();
#pragma warning restore FL0028
```

FL0028 is enabled by default with warning severity. The **Remove redundant ThrowIfCanceled call** code fix deletes the diagnosed expression statement while preserving comments and directives. Fix All is supported. Apply the fix when a single checkpoint is sufficient; suppress the warning instead when the second checkpoint's distinct timing is intentional.
